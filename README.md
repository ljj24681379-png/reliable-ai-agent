# AI 产品可靠性实验

> 当 Agent 真正进入业务，如何让结果可相信、可追溯、可控制。

**状态：第一版已完成 · 对比 Demo 可运行**

## 项目是什么

这是一个脱敏经营数据 Agent 实验。同一个问题——“昨天北京区域销售额是多少？”——分别经过普通模式和可靠模式处理，用来展示“直接给答案”和“带证据交付”的产品差异。

## 为什么做

数据 Agent 的风险不只来自答案错误。用户还需要知道系统是否真的查询、使用了什么参数、数据是否最新，以及发生冲突时系统会不会继续生成一个看起来正确的结果。

## 第一版为什么不够

普通模式只执行一次查询并回答：

```text
用户问题 → 单次查询 → 生成答案
```

这条路径很快，但数据正确性、查询过程、异常状态和权限边界都不可见。工具失败后如果仍继续生成，语言流畅度会掩盖真实风险。

## 可靠版本：四个机制

### 1. 双路校验

主查询与独立复核结果一致才直接返回；不一致则标记异常、停止确定性回答并进入人工确认。

### 2. 可信等级

| 等级 | 条件 | 产品动作 |
| --- | --- | --- |
| A | 两路一致，证据完整 | 正常交付 |
| B | 单路成功，证据完整 | 带限制说明交付 |
| C | 只能使用历史数据 | 明确数据时效 |
| D | 结果冲突或权限异常 | 停止回答，转人工 |

### 3. 可追溯

记录查询时间、数据日期、参数、工具调用和计算过程，让用户与审核者可以复查答案从哪里来。

### 4. 异常接管

查询失败、数据冲突、权限异常时不继续补写答案。页面说明失败节点、已完成检查和人工需要确认的内容。

## Demo

页面左右对比同一问题：左侧是普通 Agent 的即时答案，右侧是可靠 Agent 的校验流程、可信等级、证据轨迹和异常接管。可以切换“结果一致”和“结果冲突”两个状态，直接观察系统何时交付、何时停止。

## 产品判断

可靠性不等于承诺永不出错。更现实的目标是：正确有证据、错误能发现、异常不扩散、责任可交接。对高风险任务，多一次校验和清晰的等待状态可能比即时回答更重要。
